# Internationalization (i18n)

Privé ships in **English** (default) and **Spanish**. Every piece of user-facing text goes through
[react-i18next](https://react.i18next.com/).

## Files

```
frontend/src/
├── i18n.ts           # i18next setup, supported languages, fallback
└── locales/
    ├── en.json       # source of truth — every key must exist here
    └── es.json
```

## Rules

1. **Never hardcode UI text** in components — including `aria-label`, `title`, placeholders and toasts.
2. Add new keys to **all** locale files in the same change.
3. Translate **values**, never **keys**.
4. Keys are nested by area: `chatList.empty`, `settings.language.title`, `errors.whatsapp.sendFailed`.
5. Engine-specific text goes under `engines.<engineId>.*`.
6. Use interpolation and plurals instead of string concatenation:

   ```json
   {
     "chatList": {
       "unread_one": "{{count}} unread message",
       "unread_other": "{{count}} unread messages"
     }
   }
   ```

   ```tsx
   const { t } = useTranslation();
   t("chatList.unread", { count });
   ```

7. Brand names (WhatsApp, Telegram) are not translated.

## Backend messages

The Go backend never sends text the user reads. It sends **codes** that are keys in the locale files:

```json
{ "code": "errors.whatsapp.sendFailed", "params": { "reason": "timeout" } }
```

```tsx
t(error.code, error.params);
```

If a code is missing from the locale file, the UI shows `errors.unknown`. Keep backend codes and locale keys in sync.

## Language selection

1. The language saved in Settings (stored locally in SQLite), if any.
2. Otherwise the operating system language (detected by the Go backend in `internal/platform`).
   A regional tag matches its base language: `es-MX` → `es`.
3. Otherwise English.

The resolution lives in `resolveLanguage()` in `frontend/src/i18n.ts`.

## Type safety

`frontend/src/i18next.d.ts` types `t()` against `en.json`, so `t("typo.key")` fails `npm run typecheck`.
Keys that arrive from the backend at runtime go through `translateCode()` in `frontend/src/lib/errors.ts`,
which falls back to `errors.unknown`.

## Adding a new language

1. Copy `frontend/src/locales/en.json` to `frontend/src/locales/<code>.json`,
   where `<code>` is a BCP 47 code (`fr`, `pt-BR`, `de`).
2. Translate every value. Keep placeholders like `{{count}}` untouched.
3. Register it in `frontend/src/i18n.ts`, in `supportedLanguages` and in the `localeKeysMatch` check:

   ```ts
   import fr from "./locales/fr.json";

   export const supportedLanguages = {
     en: { translation: en },
     es: { translation: es },
     fr: { translation: fr },
   } as const;

   export const localeKeysMatch = { en: true, es: true, fr: true };
   ```

4. Add the language's **native name** to `settings.language.options` in **every** locale file
   (e.g. `"fr": "Français"`), so it appears in the language selector.
5. Run `npm run typecheck` (it verifies every locale has the same keys as `en.json`) and open a pull request.

The recovery phrase is shown in English for languages without their own word list, and that is fine:
any list unlocks the data. A word list for a new language is a separate, careful contribution (2,048 words,
rules in `internal/crypto/wordlists/wordlists.go`, frozen forever once released), so it is never required
to add a language.
